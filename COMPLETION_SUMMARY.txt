================================================================================
                          🔄 FLUJO DE DATOS COMPLETO
================================================================================

ESCENARIO 1: Usuario Envía Contacto
─────────────────────────────────────

  Usuario rellenan formulario en Principal_Page
           ↓
  POST /api/public/contact (sin auth)
           ↓
  Backend valida con ContactInquirySchema
           ↓
  ContactService.create_inquiry() genera inquiry_code
           ↓
  Se inserta en tabla contact_inquiry
           ↓
  Status automático: "new"
           ↓
  ✅ Consulta disponible para admin

ESCENARIO 2: Admin Ve Consultas
───────────────────────────────

  Admin abre Dashboard
           ↓
  MessagesModule.tsx carga
           ↓
  GET /api/admin/stats (con JWT)
           ↓
  Backend retorna: total, nuevas 24h, pendientes, sin leer
           ↓
  Mostrar estadísticas en 4 tarjetas
           ↓
  GET /api/admin/inquiries (filtrado)
           ↓
  Mostrar lista de consultas
           ↓
  ✅ Admin puede seleccionar una

ESCENARIO 3: Admin Responde
────────────────────────────

  Admin selecciona consulta
           ↓
  GET /api/admin/inquiries/<id>
           ↓
  Mostrar mensaje original + mensajes previos
           ↓
  Admin escribe respuesta
           ↓
  POST /api/admin/messages
           ↓
  Backend crea mensaje con sender_type="admin"
           ↓
  Backend auto-actualiza inquiry.status = "contacted"
           ↓
  GET /api/admin/messages/<id> (reload)
           ↓
  Mostrar respuesta en conversación
           ↓
  ✅ Comunicación bidireccional completa

================================================================================
                          🔐 SEGURIDAD IMPLEMENTADA
================================================================================

✅ Endpoint público sin autenticación
   - POST /api/public/contact accesible por cualquiera
   - Validación de entrada obligatoria

✅ Endpoints admin protegidos con JWT
   - Requieren token válido en header Authorization
   - Login requerido para obtener token

✅ Validación de entrada
   - Marshmallow schemas en todas las rutas
   - Type hints en Python
   - Validación de email, longitudes, enumerables

✅ Prevención SQL Injection
   - ORM SQLAlchemy (prepared statements)
   - No hay queries de string directo

✅ CORS Configurado
   - Frontend-backend comunicación segura
   - Headers apropiados

✅ Enumerables tipados
   - Status: new, contacted, in_progress, resolved, closed
   - Urgency: low, medium, high
   - Sender_type: user, admin, anonymous, system

                          🚀 CÓMO EMPEZAR
================================================================================

1. BASE DE DATOS:
   $ mysql -u root -p < backend/migrations/add_contact_inquiry_tables.sql

2. BACKEND:
   $ cd backend
   $ source env/bin/activate
   $ pip install -r requirements.txt
   $ python wsgi.py  # Escucha en localhost:8000

3. DASHBOARD:
   $ cd "Dashboard Administrativo Integral"
   $ npm install
   $ npm run dev  # Escucha en localhost:5173

4. PRINCIPAL PAGE:
   $ cd Principal_Page
   $ npm install
   $ npm run dev

5. PROBAR:
   - Enviar formulario en Principal_Page
   - Ver que aparece en Dashboard MessagesModule
   - Admin responde
   - Mensaje aparece en conversación
   - Status se actualiza
